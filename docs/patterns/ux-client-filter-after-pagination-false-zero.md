패턴명: 페이지 일부를 클라이언트 필터한 뒤 생기는 거짓 0건
카테고리: ux
증상: 서버에서 첫 페이지 100건만 받은 뒤 클라이언트가 완료 항목을 제외하면 화면 목록이 비어 “활성 0건”으로 보이지만, 서버 집계에는 뒤 페이지의 활성 항목이 남아 있다.
원인: 페이지네이션 기준은 전체 목록인데 0건 판정 기준은 필터된 현재 페이지만 사용해, 집계와 표시 집합의 범위가 달라진다.
해결: 활성 여부를 서버/권위 CLI의 조회 조건으로 올리고 안정 정렬과 offset 또는 cursor로 활성 총계만큼 페이지를 이어 붙인다. 0건은 권위 집계가 실제 0일 때만 표시하고, 표시 건수와 집계가 다르면 부분 목록 경고를 낸다.
적용조건: 완료·보류·실패 등 상태가 섞인 큐를 페이지 단위로 읽고 UI에서 추가 필터하는 모든 운영 화면.

# 페이지 일부를 클라이언트 필터한 뒤 생기는 거짓 0건

첫 페이지가 비었다는 사실과 전체 활성 큐가 비었다는 사실은 다르다. **권위 집계 0**만 완료 상태로 렌더링하고, 목록은 같은 활성 조건으로 끝까지 페이지네이션한다.
