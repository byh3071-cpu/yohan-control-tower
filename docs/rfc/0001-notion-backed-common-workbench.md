# RFC 0001 — Notion 연동 공통 작업대

> 상태: 제안 · 2026-08-11

## 1. 배경

현재 관제탑은 프로젝트·문서·기록·벡터·Calendar를 한 앱에 통합했지만, 사용자가 실제로 작업을 시작하거나 이어가는 흐름은 기능별 탭으로 흩어져 있다. 반대로 Notion은 모바일 캡처와 문서 편집에 편하지만, 확정 지식·프로젝트 실행 상태·에이전트 근거까지 정본으로 소유하면 다시 복잡해진다.

따라서 관제탑과 Notion을 대체 관계로 보지 않는다. 관제탑은 운영 프론트, Notion은 사람용 캡처·편집·문서 미러, Yohan Brain/Git은 확정 지식의 정본으로 나눈다.

디자인 기준은 yohan-brain의 [`요한 워크스페이스 — Notion·관제탑 통합 화면 시안`](https://github.com/byh3071-cpu/yohan-brain/blob/feat/html-design-context/docs/reference/websites/yohan-workspace-notion-control-tower-concepts.md)이다. 그중 **공통 작업대 시안**을 관제탑 홈의 방향으로 사용한다.

## 2. 목표

- 홈에서 `빠른 담기`, `코파일럿 세션 시작`, `최근 작업 이어가기`, `검토 대기`를 한 흐름으로 연결한다.
- 일정·할 일·프로젝트 기능은 유지하되 홈 전체를 차지하지 않게 한다.
- Notion에 들어온 캡처·전사·초안을 API로 읽고, AI 에이전트는 MCP로 문맥을 활용할 수 있게 한다.
- 확정 결과와 근거는 사람 승인 후 Brain/Git 정본으로 승격한다.
- 모바일·카페·집 PC 사이에서 같은 항목을 다시 설명하거나 수동 재정렬하는 횟수를 줄인다.

## 3. 화면 구조

관제탑의 탭 상한 5개는 유지한다. 새 탭을 추가하지 않고 기존 `홈`의 `개요`를 공통 작업대로 개조한다.

1. **빠른 행동**: 빠른 담기, 코파일럿 세션 시작
2. **이어가기**: 최근 열었던 세션·문서·리서치·글 초안
3. **검토 대기**: 에이전트 결과, 승격 후보, 동기화 충돌
4. **생활·운영 바로가기**: Calendar, 프로젝트, 문서 라이브러리
5. **시스템 상태**: 실패·설정 누락처럼 행동이 필요한 항목만 표시

`Top 3`, 생산성 점수, 장식용 통계 카드는 기본 홈에서 제외한다. 사용자가 무엇을 해야 하는지보다 시스템을 해석하게 만드는 요소이기 때문이다.

## 4. 데이터 소유권

| 데이터 | 정본 소유자 | 관제탑 역할 | Notion 역할 |
|---|---|---|---|
| 프로젝트 실행 상태 | 각 레포 `goals/*.md` | 집계·드릴다운 | 필요 시 읽기 전용 요약 |
| 일정·개인 할 일 | Calendar 원장 | 생성·수정·표시 | 모바일 입력 후보, 자동 양방향 동기화 금지 |
| 확정 지식·규칙·스킬 | Yohan Brain/Git | 검색·승격 진입 | 사람용 미러·편집 초안 |
| 빠른 캡처·전사·코파일럿 세션 | Notion | 수집·이어가기·검토 | 생성·편집 |
| 발행 원문·발행 상태 | 각 콘텐츠 저장소 | 상태 집계·바로가기 | 초안 또는 참고 링크 |

같은 객체를 두 저장소가 동시에 수정하지 않는다. 연결에는 안정적인 외부 ID와 출처, 마지막 동기화 시각을 기록한다.

## 5. 연결 방식

- **Notion API**: 허용한 DB와 속성만 결정적으로 읽고 쓴다. 최초 범위는 세션·캡처 목록 조회와 상태 갱신으로 제한한다.
- **Notion MCP**: 에이전트가 페이지 문맥을 읽고 요약·분류·초안을 제안할 때 사용한다. 정본 승격을 자동 승인하지 않는다.
- **관제탑 API**: Notion 데이터를 홈용 얇은 DTO로 변환한다. 토큰·원본 절대경로·불필요한 페이지 본문을 브라우저에 노출하지 않는다.
- **Brain 승격**: 기존 `api/inbox` 또는 write-once 신규 파일 경로를 재사용한다. 기존 Brain 파일 덮어쓰기는 금지한다.

## 6. 단계별 범위

### 0단계 — 화면 골격

- 공통 작업대 UI를 정적·로컬 데이터로 먼저 검증
- 빠른 행동, 이어가기, 검토 대기, 바로가기의 정보 우선순위 확인

### 1단계 — 읽기 연결

- Notion 세션·캡처 DB의 허용 필드 읽기
- 실패·권한 누락·속성 변경을 빈 목록으로 위장하지 않고 표시

### 2단계 — 제한된 쓰기

- 새 캡처 생성, 세션 상태 갱신처럼 소유권이 Notion에 있는 동작만 허용
- 낙관적 잠금 또는 마지막 편집 시각으로 충돌 거부

### 3단계 — 승인 승격

- 검토한 결과를 Brain 신규 파일로 승격
- 출처 Notion 페이지 ID, 결정자, 승격 시각, 관련 프로젝트를 증거로 보존

## 7. 제외 범위

- Notion과 Git의 자유로운 양방향 문서 동기화
- 기존 Brain 파일 자동 수정
- 모든 Notion DB를 한 번에 이관하거나 통합
- 홈에 새 탭·카드·차트를 계속 추가하는 방식
- 에이전트가 프로젝트 상태·규칙·발행을 사람 승인 없이 확정하는 동작

## 8. 위험과 검증

- **소유권 혼선**: 객체별 정본 표를 API 계약과 UI에 함께 반영한다.
- **Notion 스키마 변경**: DB ID와 필수 속성을 시작 시 검사하고 누락을 명시한다.
- **모바일 과밀**: 432px에서 빠른 행동→이어가기→검토 순서를 유지하고 가로 넘침을 금지한다.
- **홈 비대화**: 새 요소를 추가할 때 기존 요소 하나를 흡수하거나 제거한다. 탭 상한 5개를 유지한다.
- **자동화 불신**: 마지막 동기화, 출처, 제안자, 승인 상태를 사람이 확인할 수 있게 한다.

## 9. 수락 조건

- 사용자가 카페·이동 중 Notion에서 남긴 캡처나 세션을 집 PC 관제탑에서 재설명 없이 이어갈 수 있다.
- 일정·할 일·프로젝트가 공통 작업대의 전부가 아니라 필요한 진입점으로만 보인다.
- Notion과 Brain/Git 중 어느 쪽이 정본인지 항목마다 하나로 판정된다.
- Notion 연결이 끊겨도 Brain 문서·프로젝트·Calendar의 기존 기능은 계속 동작한다.
- 실제 일주일 사용 후 쓰지 않은 카드·DB·속성을 제거할 수 있는 기록이 남는다.
