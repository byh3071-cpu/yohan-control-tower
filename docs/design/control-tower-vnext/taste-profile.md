# 요한 관제탑 디자인 취향 프로필

- Version: 1.0
- Scope: `yohan-control-tower` 전용
- Last verified: 2026-08-23 (Asia/Seoul)
- Final approver: 사용자

이 문서는 범용 디자인 교리가 아니라, 이번 제품에서 대화와 시안 비교로 확인된 취향의 정본이다. 공통 작업 방식은 Yohan Agent Kit의 `design-team`이 소유하고, 여기에는 관제탑에만 적용되는 선택과 금지 패턴을 남긴다.

## 확인된 취향

- 한국어를 기본으로 쓰고 `스킬`, `MCP`, `훅`, `에이전트`, `플러그인`처럼 이미 익숙한 기술 용어는 원문을 유지한다.
- 큰 제목·부제·본문·보조 정보가 한눈에 구별되는 강한 위계를 선호한다. 같은 굵기와 비슷한 크기의 문장이 연속되는 화면은 피한다.
- 행 중심의 조밀한 목록은 좋지만 제목, 상태, 날짜, 관계가 서로 붙어 보일 정도로 압축하지 않는다.
- 실제 브랜드 아이콘과 명확한 Lucide 아이콘을 쓴다. 이모지, 깨진 글리프, 임의 도형으로 도구를 대신하지 않는다.
- 3안의 명확한 행 구조와 도구 인지성, 2안의 간결한 골격과 문서·관계 표현을 함께 사용한다.
- 검정 일색보다 Mova와 가까운 밝은 중립 셸을 선호한다. 기본 팔레트는 `#E7ECEE / #F7F9F9 / #172326 / #526367`, 제한적 강조는 `#146C94`다.
- 좌측 탐색, 중앙 작업면, 우측 검사 열의 시작선·구분선·밀도 규칙을 일관되게 맞춘다.
- 우측 검사는 내부 프롬프트 전체가 아니라 `무엇을 맡는가 / 무엇을 사용했는가 / 무엇을 남겼는가 / 무엇과 연결되는가`만 보여준다.
- 장식보다 다음 행동을 돕는 기능을 우선한다. 정렬, 안정적인 더보기 메뉴, 문서 열기, 관계 보기처럼 실제 사용 목적이 있어야 한다.

## 피해야 할 패턴

| 패턴 | 이유 | 대신 사용할 것 |
| --- | --- | --- |
| `자동화 자산`, `실행 능력`, `의사결정 레저` 같은 조어 | 뜻을 다시 해석하게 한다 | 이미 쓰는 한국어와 표준 기술 용어 |
| 진한 검정 셸과 큰 어두운 면 | 좌우 셸이 콘텐츠보다 먼저 보인다 | 밝은 Mova 중립 셸과 얇고 일관된 경계 |
| 선택 행의 파란 왼쪽 엣지 | 불필요하게 강하고 표의 정렬을 깨뜨린다 | 옅은 행 배경과 명확한 선택 상태 |
| 모든 자산에 같은 역할 조직도 | 스킬·MCP·훅·에이전트 구조가 서로 다르다 | 공통 머리말 + 종류별 상세 |
| `Codex`를 담당자나 역할로 고정 | Claude Code, Cursor, Antigravity 등 실행 환경과 역할을 혼동한다 | 역할·실행 환경·모델·관리 주체 분리 |
| 근거 없는 수량·일정·`시스템 정상` | 장식이 되고 실제 판단을 오도한다 | 출처·갱신 시각이 있는 정보만 표시 |
| 화면에 떠 있는 우측 drawer | 선택 행과 관계가 끊기고 여백이 어색하다 | 본문과 같은 그리드에 붙은 검사 열 |
| 작은 벤더 아이콘과 불균일한 여백 | 브랜드 인지가 어렵고 목록 리듬이 깨진다 | 투명 배경 실제 자산, 약 34px 광학 크기 |
| `상세`처럼 맥락 없는 반복 버튼 | 행 클릭과 기능이 중복된다 | 행 선택 또는 명시적 핵심 행동 |

## 대화와 선택 규칙

- 한 번에 중요한 디자인 결정 하나만 묻는다.
- `ㅇㅇ`, `ㄱㄱ`, `계속`, `진행`은 방금 합의한 작업을 계속하라는 뜻이며, 최종 미감 승인이나 production 구현 승인으로 확대하지 않는다.
- 사용자가 이미 고른 색·밀도·구조를 다음 세션에서 다시 처음부터 묻지 않는다. 충돌이나 새 증거가 있을 때만 재검토한다.
- 이미지 생성 성공은 전달 성공이 아니다. 채팅에 실제 렌더를 붙이고 프로젝트의 안정적인 경로를 함께 제공한다.
- 사용자가 이미지가 보이지 않는다고 하면 같은 revision을 먼저 다시 전달한다. 보지 못한 시안의 번호 선택을 요구하지 않는다.

## 시안 계보

- 1안: 정보량이 많고 시각 위계가 약해 기각.
- 2안: 간결한 골격과 문서·관계 표현이 좋음.
- 3안: 행 밀도와 선명한 아이콘이 가장 취향에 가까움.
- Candidate A: 2안과 3안의 장점을 Mova 밝은 중립 셸에 결합한 공통 시각 기반. 기술 QA 178/178과 Claude Code 검수에서 새 P0/P1 없음.

Candidate A의 기술 통과는 최종 미감 승인과 다르다. 현재 상태는 `공통 시각 기반 선택`, `사용자 미감·밀도 승인 대기`, `production 구현 미승인`이다.

## 다음 화면에서 확인할 축

- 우측 검사 열을 360px로 고정할지, 344–400px 범위에서 조절할지
- 긴 source/ref와 반복되는 릴리스 상태를 어느 밀도로 축약할지
- `지금` 화면에서 항상 보일 정보와 필요할 때만 보일 정보를 어떻게 나눌지
- `작업` 아래 `할 일 / 일정 / 프로젝트`를 형제 보기로 두는 구성이 실제 진입성을 높이는지
- 관계의 기본 표현을 목록으로 두고 그래프를 보조로 둘지
- 캘린더의 기본을 주간과 월간 중 무엇으로 둘지

이 항목은 실제 시안과 과제로 검증하며, 추측만으로 확정하지 않는다.
