# 관제탑 시각 위계 계약

- Status: selected direction · native prototype validation
- Basis: 사용자 피드백 + Mova 기본 작업 셸
- Scope: 2안의 간결한 골격과 3안의 종류별 상세를 결합하는 다음 시안

## 문제 진단

기존 2·3안은 페이지 제목, 목록 제목, 검사 열 제목, 자산 이름의 크기와 굵기가 비슷해 한 화면에 주인공이 여러 개였다. 작은 메타 글자와 반복된 굵은 제목이 동시에 많아 시선이 어디서 시작해야 하는지 약했다. [확신 높음]

다음 시안은 `페이지 → 선택 항목 → 섹션 → 본문 → 메타`의 다섯 단계만 쓴다. 같은 영역 안에 같은 크기의 1순위 제목을 두 개 만들지 않는다.

## 타입 스케일

| 역할 | 크기 / 줄높이 | 굵기 | 사용처 |
| --- | --- | ---: | --- |
| 페이지 제목 | 24 / 32px | 700 | 화면당 하나 |
| 선택 항목 제목 | 18 / 26px | 600 | 검사 열 자산명 |
| 섹션 제목 | 15 / 22px | 600 | 종류별 상세 구획 |
| 설명 본문 | 16 / 26px | 400 | 한 줄 설명과 읽기 문장 |
| 표·상세 데이터 | 14 / 21px | 400–600 | 목록, 상태, 레이블과 값 |
| 메타 | 14 / 20px | 400–600 | 시각·출처·보조 상태 |

- 굵기는 화면 전체에서 400·600·700 세 단계만 주로 쓴다.
- 한국어 제목에 영문식 과도한 자간을 넣지 않는다.
- 한 줄 설명은 최대 두 줄이며, 메타를 설명문 속에 섞지 않는다.
- 표 헤더는 본문보다 작게 만들 수 있지만 색과 굵기로 열 이름임을 분명히 한다.
- native prototype은 승인된 로컬 Pretendard 파일이 없으므로 `Malgun Gothic → Apple SD Gothic Neo → Noto Sans KR → sans-serif` 시스템 스택을 사용한다. Windows에서는 `Malgun Gothic` 가용 여부와 실제 브라우저 렌더를 측정하며, 로컬 폰트 파일을 프로젝트에 보존하기 전에는 Pretendard 사용을 주장하지 않는다.

## 공간과 정렬

- 상단 바: 52–56px
- 왼쪽 탐색: 208–216px, 접으면 56px
- 오른쪽 검사 열: 기본 288px, 내용에 따라 320px까지; 사용자가 닫거나 조절 가능
- 중앙 본문: 항상 가장 넓은 영역, 최소 720px
- 목록 행: 56–60px. 현재 interactive asset row는 44px 버튼과 상하 6px 셀 여백을 합친 CSS 58px을 기준으로 하며, Windows 실제 측정값도 60px 이하여야 한다.
- 검사 열 좌우 여백: 20px
- 검사 열 섹션 간격: 24px
- 레이블과 값 사이: 8px 이상
- 두 관계 행 사이: 16px 이상

검사 열이 닫히면 그리드 열 자체를 제거해 중앙을 즉시 넓힌다. 왼쪽 탐색, 중앙, 오른쪽 검사 열의 시작선과 1px 경계를 같은 그리드에 맞춘다.

## 색과 표면

검정 패널을 기본 표면으로 사용하지 않는다. Mova의 밝은 중립 셸을 계승한다.

- 앱 바탕: 차가운 안개색 `#E7ECEE`
- 주 작업면: 종이색 `#F7F9F9`
- 기본 텍스트: 잉크색 `#172326`
- 보조 텍스트: 슬레이트 `#526367`
- hover 후보: `#EEF3F6`
- selected 후보: `#E7EFF5`
- 현재 위치·주요 포커스: `#146C94`
- 주의가 필요한 상태: `#A84F18`

왼쪽과 오른쪽 패널은 서로 다른 검정 면과 흰 면으로 나누지 않는다. 같은 중립 계열을 쓰고 1px 경계, 선택 배경, 여백으로만 역할을 구분한다. 초록·빨강은 실제 상태가 있을 때만 쓴다.

## 화면별 강약

### 왼쪽 탐색

- 제품명은 작고 조용하게 둔다.
- 상위 항목은 아이콘 18–20px와 14px 레이블을 사용한다.
- 선택 상태는 옅은 푸른 회색 배경과 굵기 변화로 표시한다.
- 하단에는 `연결 관리`와 `설정`을 둔다. `시스템 정상`은 문제가 없을 때 숨기고, 확인이 필요할 때만 `연결 관리 · 2`처럼 배지를 표시한다.

### 중앙 목록

- 페이지 제목 하나가 시선을 시작한다.
- 검색, 종류 필터, 보기 옵션은 한 줄에 정렬한다.
- 열보다 행이 먼저 읽히도록 행 이름만 600, 나머지는 400–500을 쓴다.
- 모든 상태에 색 점을 붙이지 않는다. 확인이 필요한 상태만 의미색을 쓴다.

### 오른쪽 검사 열

- 상단 `상세` 같은 중복 제목을 생략하고 선택 항목 이름부터 시작한다.
- 공통 머리말 뒤 종류별 섹션만 표시한다.
- 섹션 제목은 15px, 설명은 16px, 데이터와 메타는 14px으로 고정한다.
- 섹션마다 카드 테두리를 반복하지 않고 큰 구분선과 여백을 사용한다.
- 핵심 행동은 하단 한 개를 우선하고 나머지는 보조 버튼 또는 메뉴로 둔다.

## 다음 시안의 결합 방향

2안의 간결한 목록 골격과 3안의 단순한 검사 열을 결합한다. 2안의 고정 역할자 표현과 3안의 모든 항목 공통 역할 영역은 버린다.

- 중앙: 실제 종류명 기반의 얇은 필터와 5열 목록
- 오른쪽: `kind`에 따라 바뀌는 다형 상세
- 실행 기록이 선택된 경우에만 역할·클라이언트·모델·도구 영수증 표시
- 1440×1024에서 `스킬 / MCP / 훅 / 플러그인` 네 선택 상태를 같은 셸로 검증

## 거부 패턴

- 한 화면에 20px 이상 굵은 제목을 네 개 이상 반복
- `Codex`를 담당자·저자·역할로 고정
- 모든 종류에 역할 조직도, 설치 버튼, 연결 상태를 강제
- `자동화 자산`, `실행 능력`처럼 설명이 필요한 조어를 기본 탐색에 사용
- `기타` 하나에 여러 raw kind를 숨김
- 정상 상태를 상시 초록색으로 장식
- 좌·우 패널의 경계 규칙과 시작선이 서로 다름
- 짙은 검정 면이 중앙 작업보다 더 먼저 보임

## 래스터 시안의 한계

ImageGen 시안은 위계·밀도·영역 구성을 선택하기 위한 미리보기다. 작은 한글 glyph, 정확한 px 폭, reflow, focus, keyboard, scroll, sticky 동작의 증거가 아니다. 특히 2026-08-22 종류별 상태에서 `훅`이 `흑`으로 반복 오렌더링됐으므로, 승인 뒤 native prototype에서 실제 글꼴과 텍스트를 사용해 다시 측정한다.
