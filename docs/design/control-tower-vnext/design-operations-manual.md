## 세션 시작

새 디자인 세션은 시안을 만들기 전에 다음 순서로 복원한다.

1. 저장소 규칙과 현재 Git branch/ref를 확인한다.
2. `design-context.md`, `taste-profile.md`, `session-handoff.md`를 읽는다.
3. `decision-log.md`, 최신 QA, 마지막 승인 가능한 시각 산출물을 확인한다.
4. 현재 상태를 `탐색 / 방향 선택 / 최종 승인 / production 승인` 중 하나로 명시한다.
5. 수신 확인으로 `읽은 기준 ref / 현재 승인 상태 / 바로 할 한 가지`를 보고한다.

문서와 실제 파일이 충돌하면 문서를 조용히 신뢰하지 말고 차이를 먼저 보고한다.

## 화면 설계 루프

1. 화면이 답해야 할 한 문장을 정한다.
2. 항상 필요, 가끔 필요, 기본 화면에는 불필요한 정보로 나눈다.
3. 색만 다른 변형이 아니라 정보 구조가 다른 대안을 만든다.
4. 한 번에 한 화면, 한 중요한 결정을 사용자와 검토한다.
5. 선택 이유와 기각 이유를 `decision-log.md`에 기록한다.
6. 데스크톱 1440px에서 방향을 확인한 뒤 360px 상태를 설계한다.
7. 기술 검증과 사용자 미감 승인을 별도 게이트로 남긴다.

## 사용자와 티키타카

- 한국어를 기본으로 하고 꼭 필요한 고유명사·기술 용어만 영어로 둔다.
- 제목, 부제, 본문, 보조 정보의 강약을 화면과 설명 모두에서 지킨다.
- 설명보다 실제 렌더를 먼저 보여주고, 무엇이 달라졌는지 짧게 말한다.
- 해결된 취향을 반복 질문하지 않는다.
- 사용자의 짧은 진행 신호는 바로 앞의 작업만 승인한 것으로 해석한다.
- 새로운 화면군으로 넘어가기 전에 현재 화면의 승인 상태를 한 줄로 고정한다.

## 승인 상태

| 상태 | 의미 | 허용되는 다음 행동 |
| --- | --- | --- |
| 계속 진행 | 바로 앞에서 합의한 조사·수정·검증을 이어감 | 같은 범위의 다음 작업 |
| 방향 선택 | 공통 시각 또는 정보 구조의 기준을 선택함 | 선택 방향 정교화와 다음 화면 탐색 |
| 최종 디자인 승인 | 화면군의 미감·밀도·상호작용을 사용자가 승인함 | production 매핑 준비 |
| production 구현 승인 | 실제 UI 코드 변경을 승인함 | 구현·테스트 |

`계속 진행`이나 기술 QA 통과를 `최종 디자인 승인`으로 승격하지 않는다.

## 시각 전달 영수증

각 시안은 다음 네 항목이 있어야 전달 완료로 본다.

- revision 또는 파일명
- 채팅에서 실제 보이는 렌더
- 프로젝트 안의 안정적인 상대경로
- 사용자가 검토해야 할 한 가지 결정

상태는 `prepared → sent → acknowledged`로 기록한다. 도구가 성공했더라도 사용자가 보지 못했으면 `sent`가 아니다. 재전달이 실패하면 텍스트 선택 질문을 반복하지 말고 안정적인 파일 링크나 새 렌더로 복구한다.

## 다음 화면 순서

Candidate A의 공통 시각 기반을 유지하면서 다음 순서로 화면을 설계한다.

1. `지금` — 지금 무엇을 이어가고 승인하고 풀어야 하는지
2. `작업` — 할 일, 일정, 프로젝트 사이의 빠른 이동
3. `지식·디자인` — 문서, 디자인 지식, 결정, 시안과 역링크
4. `운영 기록` — 실행·검증·변경 근거의 시간 흐름
5. capture overlay — 전역 입력은 작게 유지하고 어느 화면에서든 접근

한 화면이 승인되기 전에 다음 화면의 세부 시안을 과도하게 만들지 않는다.

## 검수

- 정보 구조: 화면의 한 문장에 직접 기여하는가
- 시각 위계: 3초 안에 제목, 우선 행동, 상태를 구별할 수 있는가
- 용어: 설명 없이 이해되는 기존 용어인가
- 관계: 출처와 역링크가 실제 데이터 계약에 근거하는가
- 접근성: 키보드, focus, 대비, 작은 폭에서 의미가 유지되는가
- 기술성: 실제 컴포넌트·아이콘·responsive 규칙으로 구현 가능한가
- 적대 검토: 같은 제작자가 놓친 P0/P1을 독립 검수자가 찾게 한다

## 세션 종료와 인수인계

종료 전에 다음을 프로젝트 Git에 보존한다.

- 현재 branch/ref와 마지막 검증 commit
- 선택·거절·미결 상태
- 최신 시각 산출물과 QA 근거
- 다음 세션이 바로 할 한 가지
- production 구현 승인 여부
- 전달 상태 `prepared / sent / acknowledged / failed`

새 세션이 `기준 ref / 현재 게이트 / 다음 행동`을 되말하기 전까지 인수인계는 완료가 아니다.
