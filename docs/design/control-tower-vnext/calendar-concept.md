# 관제탑 일정 화면 구상

## 한 줄 원칙

관제탑 일정 UI는 또 하나의 복제 원장이 아니다. Calendar markdown을 일정 SoT로 읽고, “언제 무엇을 검토하거나 이어갈 것인가”를 프로젝트·Goal·문서·디자인 관계 위에 시간축으로 보여주는 보기다.

## 위치

- 상위 탐색을 여섯 개로 늘리지 않는다.
- Home의 `지금` 화면에는 오늘 일정 최대 세 건만 둔다.
- **Proposed** — 전체 `할 일 / 일정 / 프로젝트`는 `작업` 상위 영역 안에서 각각 직접 선택 가능한 형제 보기로 둔다.
- 일정 항목을 선택하면 스킬·문서와 동일한 우측 `작업 맥락` 검사 열을 사용한다.

## 구분해야 할 일정

| 유형 | 의미 | 완료 방식 | 시각 구분 |
| --- | --- | --- | --- |
| 약속 | 실제 시간이 정해진 개인·외부 일정 | 시간 경과 또는 사람 확인 | 시계 아이콘, 중립색 |
| 작업 블록 | 특정 Goal을 이어가기 위해 확보한 시간 | 실행 기록 또는 사람 완료 | 재생 아이콘, 파란색 |
| 검토 | 사람 선택·승인이 필요한 시점 | 승인·거절·보류 결정 | 눈/확인 아이콘, 주황색 |
| 마감 | 결과가 준비돼야 하는 경계 | Goal 또는 산출물 상태 | 깃발 아이콘, 빨간색은 임박·초과만 |
| 자동 작업 | 예약된 로컬 실행 | 실행 영수증 | 번개 아이콘, 보라색 |

개인 약속, Goal 마감, 자동 작업은 서로 다른 완료 의미를 가지므로 자동 병합하지 않는다.

## 전체 화면

- 기본은 실제 데이터 밀도에 따라 주간 또는 월간 보기를 선택하며, 첫 구현 전 최근 4주의 일정 수를 확인한다.
- 상단에는 날짜 이동, 오늘, 보기 전환, 유형 필터만 둔다.
- 본문은 하루의 시간축과 종일 영역을 구분한다.
- 항목 라벨은 `시간 / 제목 / 연결 프로젝트`까지만 보이고 상태·근거는 검사 열로 이동한다.
- 겹친 일정은 폭을 무리하게 줄이지 않고 묶음으로 접는다.
- 일정이 없는 날은 빈 카드 대신 여백을 유지한다.

## 일정 선택 시 작업 맥락

1. 제목, 시간, 유형, 상태
2. 연결 프로젝트·Goal
3. 준비 문서와 관련 스킬·작업팀
4. 최근 결정 또는 막힘
5. 이전·다음 관련 일정
6. 행동: `프로젝트 열기`, `문서 열기`, `검토 시작`

예: `디자인 수정 시안 검토`는 `관제탑 vNext`, `design-team`, `design-spec.md`, 선택 시안, 결정 로그에 역링크된다.

일정이 스킬의 속성은 아니다. 관계 방향은 `Calendar 일정 —예정된다→ 검토 요청/산출물`이며, 스킬 상세에서는 검증된 역링크가 있을 때만 `관련 검토`로 보인다. 관계가 없으면 섹션 전체를 숨긴다.

## 할 일과 일정의 경계

- `할 일` 보기는 Calendar `task`와 프로젝트 Goal의 다음 행동을 한 화면에서 읽되 출처 배지와 완료 의미를 분리한다.
- Calendar `task` 완료는 Calendar 원장에만 쓰고 프로젝트 Goal 완료로 동기화하지 않는다.
- Goal은 날짜가 있어도 프로젝트 실행 정본이며 Calendar 일정으로 자동 복제하지 않는다.
- 사용자는 `할 일`과 `일정`을 좌측 중첩 탐색에서 각각 바로 열 수 있다. 데스크톱에서는 이 세 자식을 현재 화면과 관계없이 항상 보여 한 번의 클릭으로 접근한다. 이는 독립 화면이지만 동일한 `작업` 상위 범위를 공유한다.

## Home의 오늘 일정

- 최대 세 건을 시간순으로 표시한다.
- 가장 가까운 일정은 시간·제목·연결 프로젝트를 한 줄로 보인다.
- 검토 일정은 일반 약속보다 먼저 강조하되 실제 시작 시간 순서는 바꾸지 않는다.
- 세 건을 넘으면 `전체 일정 보기` 한 줄로 합친다.
- Goal이 날짜만 있고 시간이 없으면 종일 `마감`으로 표시하며 개인 약속처럼 보이지 않게 한다.

## 실패·불확실 상태

- 원본 파일을 읽지 못하면 마지막 확인 시각과 함께 `일정 원본 확인 필요`로 표시한다.
- 연결된 Goal이나 문서가 사라졌으면 일정을 삭제하지 않고 `연결 끊김` 상태로 남긴다.
- 날짜 충돌이나 timezone 미확인은 자동 보정하지 않고 사람 확인을 요구한다.
- 반복 일정 수정은 단일 항목과 전체 반복 범위를 명확히 분리한다.

## 검증 질문

- 오늘 해야 할 일과 시간이 정해진 약속을 5초 안에 구분할 수 있는가?
- 일정에서 연결 Goal·문서·작업팀으로 한 번에 이동할 수 있는가?
- 검토가 필요한 일정이 사람 승인 없이 완료 상태가 되지 않는가?
- 360px 모바일에서 종일 일정, 시간 일정, 겹친 일정이 잘리지 않는가?
- 일정 원본이 끊겨도 마지막 확인 정보와 복구 경로가 보이는가?
