# 요한 관제탑 vNext 선택 방향 명세

- Status: selected · refinement pending
- Visual basis: 3안 중심, 2안의 문서 관계 표현 결합
- Target viewport: desktop 1440×1024
- Human gate: 우측 검사 열의 구성·밀도·관계 표현 승인

## 디자인 명제

관제탑은 “많은 정보를 보여주는 대시보드”가 아니라, 현재 항목과 그 항목을 움직이는 사람·도구·문서·결정·일정을 한 경로로 확인하는 운영 화면이다. 기본 화면은 조밀한 목록을 유지하고, 선택한 한 항목의 맥락만 우측 검사 열에서 깊게 본다.

## 선택한 시각 언어

- 왼쪽 탐색과 전역 헤더는 저채도 흑연색, 작업면과 검사 열은 따뜻한 밝은 회색을 쓴다.
- 선택은 파란 세로선, 옅은 파란 행 배경, 파란 focus ring으로 일관되게 표현한다.
- 항목 유형은 Lucide 계열 선 아이콘, 연결 도구는 실제 브랜드 아이콘을 사용한다. 이모지, 텍스트 기호, 장식용 로고 반복은 사용하지 않는다.
- 큰 카드의 중첩을 피하고 1px 구분선, 행, 섹션 제목, 여백으로 위계를 만든다.
- 본문 16px 이상, 보조 문구 14px 이상을 기준으로 한다. 촘촘함은 글자를 줄이지 않고 열과 표시 정보를 줄여 해결한다.

## 전체 그리드

| 영역 | 1440px 기준 | 규칙 |
| --- | ---: | --- |
| 왼쪽 탐색 | 200px | 고정, 다섯 상위 항목과 하단 시스템 상태 |
| 중앙 작업면 | minmax(680px, 1fr) | 목록·필터·주요 작업 소유 |
| 작업 맥락 검사 열 | 360px | 선택 시 고정 열, 본문을 덮지 않음 |

- 전역 헤더와 검사 열 헤더의 위쪽 시작선은 같다.
- 중앙과 검사 열 사이에는 1px 세로 구분선만 두고 이중 바깥 여백을 만들지 않는다.
- 검사 열 내부 좌우 여백은 24px, 섹션 사이 24px, 행 사이 12px를 기본으로 한다.
- 검사 열이 열리면 중앙 표의 보조 열부터 감춘다. 이름·역할·수명주기·설치·검증은 유지한다.
- 1280px 미만에서는 검사 열이 sheet로 전환되지만 전역 헤더 바로 아래에서 시작하며 선택한 행으로 쉽게 돌아갈 수 있어야 한다.

## 스킬·도구 화면

### 목록

목록 열은 `이름 / 역할 / 수명주기 / 사용 도구 / 설치 / 검증`으로 구성한다.

- `수명주기`: 후보 · 검토됨 · 배포됨 · 보관
- `설치`: 미설치 · 설치됨 · 일부 설치 · 설치 오류
- `검증`: 미검증 · 검토 중 · 독립 검토 통과 · 검토 필요 · 오류
- 동일 의미를 `배포됨`으로 중복 표시하지 않는다.
- 정본 값과 현재 PC 설치 상태를 분리한다. Agent Kit 정본과 실제 설치 결과가 다를 수 있기 때문이다.

### `design-team` 선택 상태

검사 열은 다음 순서로 읽힌다.

1. **요약** — `design-team`, “프로젝트 맥락을 기억하며 필요한 역할만 구성하는 디자인 작업팀”, 수명주기·설치·검증 상태
2. **구성** — `지휘 / UX / 조사 / 시각 / 기술 / 검토` 여섯 역할을 아이콘과 한 줄 책임으로 표시
3. **사용 스킬·도구** — 선택된 스킬 자신은 제외하고, 현재 실행에서 실제로 사용한 다른 스킬과 도구만 작은 연결 행으로 표시
4. **참조 문서** — DesignContext, 연구, 결정 기록, 디자인 명세
5. **관계** — `design-team —만들었다→ 수정 시안`, `사용자 —선택했다→ 3안`처럼 관계 동사와 사람 결정 경계를 분리한 짧은 경로와 역링크 수
6. **최근 근거** — 조사 완료, 시안 비교, 독립 검토처럼 결과를 만든 기록
7. **다음 일정** — 가장 가까운 사람 검토 한 건
8. **행동** — `문서 열기`, `관계 보기`, `관련 기록 보기`

역할은 고정 조직도가 아니다. 프로젝트별로 실제 구성된 역할만 보이며 모델명·provider는 필요할 때 `실행 영수증`의 보조 정보로만 노출한다.

## 작업 맥락 검사 열의 콘텐츠 규칙

- `무엇인가 → 누가/무엇이 구성하는가 → 어떤 근거와 연결되는가 → 다음 행동은 무엇인가` 순서를 유지한다.
- 이름, 책임, 상태, 최신 시각, 출처, 관계를 우선하고 장문의 설명은 연결 문서에서 읽는다.
- 프롬프트 전문, 숨은 사고 과정, 시크릿, 인증 값, 비공개 설정은 표시하지 않는다.
- 값이 없으면 `없음`, 확인하지 못했으면 `확인 필요`, 오래됐으면 `오래됨`으로 구분한다.
- 연결 상태와 검증 상태를 같은 초록 점으로 합치지 않는다.
- 검사 열 본문은 독립 세로 스크롤을 허용하고 하단 행동은 sticky footer로 유지한다.
- 기본 노출 상한은 구성 역할 6개, 사용 스킬·도구 4개, 참조 문서 4개, 최근 근거 3개다. 넘치면 `+N 더 보기`로 접고 전체 목록을 검사 열 안에 무한히 늘이지 않는다.

## 문서 라이브러리와 디자인 지식

- `지식·자산` 아래에서 `문서 / 디자인 / 자산`을 화면 내부 보기로 제공한다.
- 디자인 문서는 `기준 / 참고 / 결과물 / 피할 패턴 / 결정 기록`으로 구분한다.
- 문서를 선택하면 출처, Git 근거, 적용 범위, 파생 관계, 역링크, 최근 결정을 같은 검사 열에서 보여준다.
- Design Intelligence는 문서 사본을 만드는 별도 저장소가 아니라 프로젝트 Git의 산출물과 Brain의 provenance/index를 연결해 탐색·비교·검토하는 층이다.
- 현재 validator 오류가 있으면 `정상`으로 꾸미지 않고 영향받는 관계와 허용되는 read-only 행동을 표시한다.

## 일정 연결

- Home에는 `오늘 일정`만 압축해 보여준다.
- 전체 캘린더는 상위 탭을 추가하지 않고 `지금` 화면의 보기 전환으로 제공한다.
- 일정은 프로젝트, Goal, 검토 요청, 문서, 디자인 시안과 관계를 가질 수 있고 같은 검사 열에서 역링크를 본다.
- 개인 약속과 작업 마감은 시각과 필터를 분리하며 자동으로 하나의 완료 의미로 합치지 않는다.

## 상호작용

- 행 선택은 검사 열을 열고 URL 또는 선택 상태를 남겨 새로고침 후 복원한다.
- `Esc`는 검사 열을 닫고 포커스를 선택했던 행으로 되돌린다.
- `↑/↓`는 목록 행 이동, `Enter`는 선택, `Cmd/Ctrl+K`는 전역 검색·명령을 연다.
- 관계 항목 선택은 현재 검사 열 안에서 breadcrumb를 쌓되 두 단계 이상이면 전용 관계 보기로 이동한다.
- 위험하거나 쓰기를 일으키는 행동은 검사 열의 기본 버튼에 놓지 않는다.

## 반응형 변환

- 1440px 이상: 200px / 유동 중앙 / 360px의 세 열.
- 1280–1439px: 왼쪽 탐색 184px, 검사 열 344px, 표의 사용 도구 보조 텍스트 축소.
- 768–1279px: 탐색 축소, 검사 열은 오른쪽 sheet, 선택 행·제목을 상단에 고정.
- 767px 이하: 목록은 행 카드로 바뀌고 검사 맥락은 전체 화면 상세로 이동한다. 정보 순서는 데스크톱과 동일하다.

## 접근성과 품질 기준

- 모든 클릭·터치 표적은 최소 24×24px이며 밀집 표에서는 충분한 간격을 추가한다.
- focus indicator는 2px 이상이며 주변 색과 3:1 이상 차이를 확보한다.
- 상태는 색만으로 전달하지 않고 텍스트와 아이콘을 함께 쓴다.
- 브랜드 아이콘에는 도구 이름의 접근 가능한 이름을 제공한다.
- 1440·1280·768·432·360px에서 overflow, 잘림, 겹침, 이중 스크롤을 검증한다.

## 수정 시안 승인 기준

- 검사 열의 상단과 왼쪽 경계가 전역 헤더·본문 그리드에 정확히 맞는다.
- `design-team`의 여섯 역할을 5초 안에 파악할 수 있고 전체 프롬프트는 보이지 않는다.
- 참조 문서와 관계 경로, 다음 검토 일정을 한 화면에서 찾을 수 있다.
- 목록의 수명주기·설치·검증이 중복 의미 없이 구분된다.
- 3안의 명확한 아이콘과 밀도는 유지하되 14px 미만의 보조 문구에 의존하지 않는다.
- production 구현은 이 수정 시안이 사람 승인을 받은 뒤에만 시작한다.
