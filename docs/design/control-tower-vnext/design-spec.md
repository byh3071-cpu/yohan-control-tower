# 요한 관제탑 vNext 선택 방향 명세

- Status: direction selected · domain contract corrected · visual refinement pending
- Visual basis: 2안의 간결한 골격 + 3안의 종류별 상세 표현
- Target viewport: desktop 1440×1024
- Human gate: 우측 검사 열의 구성·밀도·관계 표현 승인

## 디자인 명제

관제탑은 “많은 정보를 보여주는 대시보드”가 아니라, 현재 항목과 그 항목을 움직이는 사람·도구·문서·검토·일정을 한 경로로 확인하는 운영 화면이다. 기본 화면은 정돈된 목록을 유지하고, 선택한 한 항목의 맥락만 우측 검사 열에서 깊게 본다.

## 선택한 시각 언어

- 검정 패널을 기본 표면으로 쓰지 않는다. Mova의 밝은 중립 셸을 이어 앱 바탕 `#E7ECEE`, 작업면 `#F7F9F9`, 텍스트 `#172326`, 보조 텍스트 `#526367`을 기준으로 한다.
- 선택은 `#E7EFF5` 배경과 `#146C94` focus로 일관되게 표현한다.
- 항목 유형은 Lucide 계열 선 아이콘, 연결 도구는 실제 브랜드 아이콘을 사용한다. 이모지, 텍스트 기호, 장식용 로고 반복은 사용하지 않는다.
- 큰 카드의 중첩을 피하고 1px 구분선, 행, 섹션 제목, 여백으로 위계를 만든다.
- 제목·본문·메타는 `24/32, 18/26, 15/22, 설명 16/26, 표·메타 14/21px`의 제한된 위계를 쓴다. 상세 규칙은 `visual-hierarchy-contract.md`를 따른다.
- 생성 시안의 아이콘은 방향 확인용이다. 구현에서는 `lucide-react`의 named icon과 검증된 공식 브랜드 자산만 사용하며 이모지, 깨진 glyph, 유사 로고를 허용하지 않는다.

## 전체 그리드

| 영역 | 1440px 기준 | 규칙 |
| --- | ---: | --- |
| 왼쪽 탐색 | 208–216px | 다섯 상위 항목과 하단 연결 관리·설정 |
| 중앙 작업면 | minmax(680px, 1fr) | 목록·필터·주요 작업 소유 |
| 작업 맥락 검사 열 | 288–320px | 선택 시 보조 열, 닫기·폭 조절 가능 |

- 전역 헤더와 검사 열 헤더의 위쪽 시작선은 같다.
- 중앙과 검사 열 사이에는 1px 세로 구분선만 두고 이중 바깥 여백을 만들지 않는다.
- 검사 열 내부 좌우 여백은 20px, 섹션 사이 24px, 행 사이 12px를 기본으로 한다.
- 검사 열이 열려도 중앙 표의 `이름 / 종류 / 정본·릴리스 / 지원 환경 / 현재 PC` 다섯 열을 유지한다. 검증은 선택한 항목의 공통 머리말에서 항상 보인다.
- 1280px 미만에서는 검사 열이 modal sheet로 전환된다. modal은 사용자가 항목을 선택한 뒤에만 열리고, 닫으면 선택한 행으로 포커스가 돌아가야 한다.

## 스킬·도구 화면

### 목록

현재 정본은 201개, 12종이다. `전체 / 스킬 / 에이전트 / MCP / 플러그인 / 훅 / 더보기`처럼 실제 종류명을 사용하며 새 facet 용어를 만들지 않는다. 수량은 카탈로그에서 계산하고 하드코딩하지 않는다.

공통 목록 열은 `이름 / 종류 / 정본·릴리스 / 지원 환경 / 현재 PC`로 구성한다. `정본·릴리스` 셀은 catalog lifecycle과 현재 릴리스 포함 여부를 이름 붙은 두 줄로 분리한다. 상세 계약은 `asset-detail-contract.md`를 따른다.

- `정본 단계`: 후보 · 검토됨 · 승인됨 · 배포됨 · 사용 중단
- `릴리스 포함`: 포함됨 · 제외됨 · 확인 안 됨
- `현재 PC`: 설치됨 · 누락 · 충돌 · 확인 안 됨
- `검증`: 미실행 · 통과 · 실패 · 오래됨
- 설치·연결·파싱·실행 가능 여부는 종류별 상세에서 분리한다. Rule·Config·Manifest에 일괄 `설치됨`을 적용하지 않는다.
- `released` 또는 source path 존재만으로 현재 PC 설치·runtime·검증을 추론하지 않는다.
- plugin 하위 skill·agent·hook·MCP·command는 부모가 비활성일 때 `부모 비활성`을 표시하고 독립 설치로 중복 집계하지 않는다.

### 종류별 선택 상태

검사 열은 공통 머리말 뒤 선택한 종류에 필요한 섹션만 읽는다. 스킬·에이전트·MCP·훅·플러그인·명령·규칙·설정·매니페스트·스크립트·테스트 자료·템플릿은 서로 다른 렌더러를 사용한다.

`design-team`의 역할은 정적 자산 상세에서 제거한다. 실제 실행 기록이 있을 때만 `이번 작업의 역할`을 표시하고 역할·실행 환경·모델·사용 도구를 분리한다. `Codex`를 역할자나 작성자로 표시하지 않는다.

## 작업 맥락 검사 열의 콘텐츠 규칙

- `무엇인가 → 누가/무엇이 구성하는가 → 어떤 근거와 연결되는가 → 다음 행동은 무엇인가` 순서를 유지한다.
- 이름, 책임, 상태, 최신 시각, 출처, 관계를 우선하고 장문의 설명은 연결 문서에서 읽는다.
- 프롬프트 전문, 숨은 사고 과정, 시크릿, 인증 값, 비공개 설정은 표시하지 않는다.
- 값이 없으면 `없음`, 확인하지 못했으면 `확인 필요`, 오래됐으면 `오래됨`으로 구분한다.
- 연결 상태와 검증 상태를 같은 초록 점으로 합치지 않는다.
- 검사 열 본문은 독립 세로 스크롤을 허용하고 하단 행동은 sticky footer로 유지한다.
- 기본 노출 상한은 구성 역할 6개, 사용 스킬·도구 4개, 참조 문서 4개, 최근 근거 3개다. 넘치면 `+N 더 보기`로 접고 전체 목록을 검사 열 안에 무한히 늘이지 않는다.
- 관계 한 건은 두 줄 고정 구조를 쓴다. 첫 줄은 `출발 개체 + 관계 동사`, 둘째 줄은 `대상 개체 + 상태`이며 관계 간에는 최소 16px을 둔다. 한 줄 화살표 문장으로 압축하지 않는다.

## 문서 라이브러리와 디자인 지식

- `지식·디자인` 아래에서 `전체 / 문서 / 디자인`을 기본 보기로 제공한다. 결정은 종류 필터와 상세 근거로, 관계 문제는 `확인 필요` 필터와 원인·영향·복구 경로로 제공한다.
- 디자인 문서는 `기준 / 참고 / 결과물 / 피할 패턴 / 결정 기록`으로 구분한다.
- 문서를 선택하면 출처, Git 근거, 적용 범위, 파생 관계, 역링크, 최근 결정을 같은 검사 열에서 보여준다.
- Design Intelligence는 문서 사본을 만드는 별도 저장소가 아니라 프로젝트 Git의 산출물과 Brain의 provenance/index를 연결해 탐색·비교·검토하는 층이다.
- 현재 validator 오류가 있으면 `정상`으로 꾸미지 않고 영향받는 관계와 허용되는 read-only 행동을 표시한다.

## 일정 연결

- `지금`에는 오늘 할 일과 오늘 일정만 압축해 보여준다.
- 전체 할 일·일정·프로젝트는 제안된 `작업` 상위 영역의 형제 보기로 제공한다. 이는 다섯 상위 영역 안에서의 중첩 보기이며 여섯 번째 탭을 만들지 않는다.
- 데스크톱 탐색에서는 `작업`의 세 자식 `할 일 / 일정 / 프로젝트`를 현재 화면과 관계없이 항상 펼쳐 한 번의 클릭으로 접근하게 한다. `작업` 자체는 접기 행동과 분리된 그룹 표제다.
- 일정은 프로젝트, Goal, 검토 요청, 문서, 디자인 시안과 관계를 가질 수 있고 같은 검사 열에서 역링크를 본다.
- 개인 약속과 작업 마감은 시각과 필터를 분리하며 자동으로 하나의 완료 의미로 합치지 않는다.

## 상호작용

- 행 선택은 검사 열을 열고 URL 또는 선택 상태를 남겨 새로고침 후 복원한다.
- `Esc`는 검사 열을 닫고 포커스를 선택했던 행으로 되돌린다.
- `↑/↓`는 목록 행 이동, `Enter`는 선택, `Cmd/Ctrl+K`는 전역 검색·명령을 연다.
- 관계 항목 선택은 현재 검사 열 안에서 breadcrumb를 쌓되 두 단계 이상이면 전용 관계 보기로 이동한다.
- 위험하거나 쓰기를 일으키는 행동은 검사 열의 기본 버튼에 놓지 않는다.

## 반응형 변환

- 1280px 이상: 216px / 유동 중앙 / 320px의 세 열. 1440px에서도 같은 계약을 유지한다.
- 768–1279px: 왼쪽 탐색 184px, 검사 열은 최대 380px의 오른쪽 modal sheet로 전환한다.
- 767px 이하: 목록은 행 카드로 바뀌고 검사 맥락은 전체 화면 상세로 이동한다. 정보 순서는 데스크톱과 동일하다.

## 접근성과 품질 기준

- 모든 클릭·터치 표적은 최소 24×24px이며 밀집 표에서는 충분한 간격을 추가한다.
- focus indicator는 2px 이상이며 주변 색과 3:1 이상 차이를 확보한다.
- 상태는 색만으로 전달하지 않고 텍스트와 아이콘을 함께 쓴다.
- 정본과 연결되지 않은 화면 시안은 목록과 검사 열 모두에 `예시 데이터`를 지속 표시한다. 실제로 확인된 집계값만 `정본 수량`으로 별도 표기한다.
- 브랜드 아이콘에는 도구 이름의 접근 가능한 이름을 제공한다.
- 1440·1280·1279·768·432·360px에서 overflow, 잘림, 겹침, 이중 스크롤과 panel↔modal 경계를 검증한다.

## 수정 시안 승인 기준

- 검사 열의 상단과 왼쪽 경계가 전역 헤더·본문 그리드에 정확히 맞는다.
- 스킬·MCP·훅·플러그인을 차례로 선택했을 때 각각 필요한 상세만 5초 안에 파악할 수 있다.
- 참조 문서와 관계, 실제로 연결된 검토가 있으면 그 역링크를 한 화면에서 찾을 수 있다.
- 목록의 catalog·가용·검증 상태가 중복 의미 없이 구분된다.
- 3안의 명확한 아이콘과 밀도는 유지하되 14px 미만의 보조 문구에 의존하지 않는다.
- production 구현은 이 수정 시안이 사람 승인을 받은 뒤에만 시작한다.
