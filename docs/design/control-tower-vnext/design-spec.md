# 요한 관제탑 vNext 디자인·기술 명세

- Status: verified · NOW-R3 사용자 승인 · Goal 22 production 구현·QA 완료
- Revision: CONTROL-TOWER-VNEXT-SPEC-R3.1
- Visual source: `docs/prototypes/control-tower-now-mova-r3/`
- Language source: `work-item-language-contract.md`
- Target runtime: localhost `3001`, Next.js 16 · React 19 · TypeScript strict
- Human gate: Goal 22 결과 확인 후 권장 순서 2번 `작업` 화면 Goal 범위 승인

## 디자인 명제

관제탑은 많은 상태를 전시하는 대시보드가 아니라, 지금 할 한 가지를 정하고 그 일의 목표·근거·관계를 필요할 때 확인하는 로컬 운영 화면이다.

승인된 R3의 핵심은 모든 화면을 같은 모양으로 만드는 것이 아니다. 다음 네 가지를 전 화면의 불변식으로 사용한다.

1. 화면마다 주인공은 하나다.
2. `단계 → 목표 → 작업`을 실행 계층으로 쓰고 `이슈`는 조건부 연결로만 쓴다.
3. 실제 값이 없는 이슈·담당자·기한·상태 영역은 만들지 않는다.
4. 다음 행동은 한 줄과 핵심 버튼 하나로 먼저 이해돼야 한다.

## 승인된 시각·콘텐츠 언어

- 검정 패널을 기본 표면으로 쓰지 않는다. Mova의 밝은 중립 셸을 이어 앱 바탕 `#E7ECEE`, 작업면 `#F7F9F9`, 텍스트 `#172326`, 보조 텍스트 `#526367`을 기준으로 한다.
- 선택은 `#E7EFF5` 배경과 `#146C94` focus로 일관되게 표현한다.
- 항목 유형은 Lucide 계열 선 아이콘, 연결 도구는 실제 브랜드 아이콘을 사용한다. 이모지, 텍스트 기호, 장식용 로고 반복은 사용하지 않는다.
- 큰 카드의 중첩을 피하고 1px 구분선, 행, 섹션 제목, 여백으로 위계를 만든다. 그림자와 radius는 메뉴·dialog처럼 실제 부유 계층에만 쓴다.
- `지금`과 단일 Task 상세의 H1은 데스크톱에서 최대 `54/58px`을 허용한다. 목록·검색·기록 화면의 H1은 `28–32/38px`로 낮춰 데이터 영역을 침범하지 않는다.
- 본문·행·메타는 `18/29, 16/26, 14/21px` 세 축을 기본으로 하며 화면에 보이는 설명을 14px 미만으로 만들지 않는다.
- 한국어 실제 이름을 본문에 쓰고 `PHASE / GOAL / TASK / NEXT`는 작은 고정 분류 레이블로만 쓴다.
- 상태 문구는 `대기 / 진행 / 검토 대기 / 막힘 / 완료 / 확인 필요`로 표시하되 원본 상태값은 보존한다. 닫힌집합 매핑은 코드 allowlist로 검증한다.
- 생성 시안의 아이콘은 방향 확인용이다. 구현에서는 `lucide-react`의 named icon과 검증된 공식 브랜드 자산만 사용하며 이모지, 깨진 glyph, 유사 로고를 허용하지 않는다.

## 전역 셸과 탐색

상위 탐색은 정확히 다섯 개다.

| 순서 | 화면 | 한 줄 책임 | 하위 보기 |
| ---: | --- | --- | --- |
| 1 | 지금 | 지금 할 한 가지와 필요한 사람 결정을 확정 | 없음 |
| 2 | 작업 | 할 일·일정·프로젝트를 각각의 완료 의미로 관리 | 할 일 · 일정 · 프로젝트 |
| 3 | 지식·디자인 | 문서와 디자인의 출처·적용·승인 관계를 확인 | 전체 · 문서 · 디자인 · 관계 |
| 4 | 스킬·도구 | 설치 목록이 아니라 현재 환경의 가용성과 근거를 확인 | 전체 · 실제 kind 필터 |
| 5 | 운영 기록 | 최근 실행·변경·실패 원인과 로컬 서비스 상태를 확인 | 실행 · 변경 · 진단 |

- 데스크톱은 R3처럼 상단 한 줄 탐색을 사용한다. 별도 고정 왼쪽 탐색을 동시에 두지 않는다.
- 767px 이하에서는 브랜드·현재 화면·메뉴 버튼만 남기고 다섯 항목은 modal navigation으로 연다.
- 현재 위치는 색뿐 아니라 `aria-current="page"`, 굵기, 3px 하단선으로 표현한다.
- 검색과 빠른 입력은 전역 명령 진입으로 제공하되 상단 탐색의 여섯 번째 항목이 되지 않는다.
- `Vector`는 상위 화면이 아니다. 검색은 `지식·디자인`, 인덱스·Ollama·Qdrant 상태와 ingest 기록은 `운영 기록`이 소유한다.

## 화면별 구조

### 지금

- `Phase / Goal` 한 줄 경로 → `TASK n / total · NOW` → 현재 Task H1 → 한 줄 설명 → 상태·진행·기준 시각 → 핵심 행동 하나 순서다.
- Phase가 정본에 선언되지 않았으면 Phase를 생략한다. Goal이 없거나 여러 Goal이 우선순위를 다투면 AI가 하나를 고르지 않고 각각 `진행할 작업 없음` 또는 `우선 작업 확인 필요` 상태를 표시한다.
- 완료 기준과 기준 문서는 최대 두 열로 보인다. 이슈·담당자·기한은 실제 연결 값이 있을 때만 추가한다.
- `NEXT`는 현재 Task가 끝난 뒤 실행할 한 가지다. 미래 backlog나 전체 미션 카드는 두지 않는다.
- 오늘 일정은 현재 Task의 우선순위를 바꾸는 실제 항목이 있을 때만 한 줄로 표시한다.

### 작업

- `할 일 / 일정 / 프로젝트`는 같은 화면의 형제 보기이며 한 번의 클릭으로 전환한다.
- 할 일은 Calendar Task와 Goal의 미완료 Completion Check를 출처와 함께 읽되 완료를 서로 동기화하지 않는다.
- 일정은 event·task·검토·마감의 완료 의미를 합치지 않는다. 기본 주간·월간 보기는 실제 최근 4주 밀도를 측정한 뒤 결정한다.
- 프로젝트는 `프로젝트 → Goal → Task` 순서로 읽고 Issue는 실제 링크가 있을 때만 표시한다.
- 전체 backlog, 미션 카드, 일정 홍보 문구를 기본 화면에 반복하지 않는다.

### 지식·디자인

- 목록 열은 `이름 / 종류 / 상태 / 기준 문서 또는 소유자 / 최근 확인`이다.
- 문서·디자인을 선택하면 source ref, Git ref, hash, 적용 범위, 파생 결과, 역링크, 사람 결정 근거를 조건부 상세에 표시한다.
- 관계는 목록이 기본이고 그래프는 보조 보기다. Qdrant 결과는 파생 검색 결과로 표시하고 정본 상태처럼 보이게 하지 않는다.
- 지식 검토는 사람 승인 전까지 제안 상태이며 기존 Brain 파일을 자동 수정하지 않는다.

### 스킬·도구

- `전체 / 스킬 / 에이전트 / MCP / 플러그인 / 훅 / 더보기`처럼 실제 kind를 사용한다. 수량은 런타임 카탈로그에서 계산하고 하드코딩하지 않는다.
- 목록 열은 `이름 / 종류 / 정본·릴리스 / 지원 환경 / 현재 PC`다. 설치·연결·파싱·실행·검증을 하나의 초록 상태로 합치지 않는다.
- 스킬·에이전트·MCP·훅·플러그인·명령·규칙·설정·매니페스트·스크립트·fixture·template은 `asset-detail-contract.md`의 종류별 렌더러를 쓴다.
- 현재 production에는 카탈로그 API나 화면이 없다. 구현 전 읽기 전용 데이터 계약과 API를 먼저 만들며, `rules + templates` 수를 스킬 자산 수로 대신 사용하지 않는다.
- 실제 실행 영수증이 있을 때만 역할·실행 환경·모델·사용 도구를 서로 다른 필드로 표시한다.

### 운영 기록

- `실행`은 batch·ingest·승인 요청·자동 작업 영수증, `변경`은 Git·결정 로그, `진단`은 Qdrant·Ollama·연결·validator 오류를 소유한다.
- 정상 숫자를 상시 장식하지 않는다. 최근 실패나 확인 필요가 있을 때 원인·영향·복구 경로를 먼저 표시한다.
- reset·publish·배포·기존 Brain 수정 같은 고위험 행동은 기본 목록 행동으로 두지 않고 별도 사람 게이트를 유지한다.

## 조건부 상세 영역

- `무엇인가 → 누가/무엇이 구성하는가 → 어떤 근거와 연결되는가 → 다음 행동은 무엇인가` 순서를 유지한다.
- 이름, 책임, 상태, 기준 시각, 출처, 관계를 우선하고 장문의 설명은 연결 문서에서 읽는다.
- 프롬프트 전문, 숨은 사고 과정, 시크릿, 인증 값, 비공개 설정은 표시하지 않는다.
- 값이 없는 섹션은 숨긴다. 필수 값이지만 읽지 못했으면 `확인 필요`, 확인 시각이 유효 기간을 넘겼으면 `오래됨`으로 구분한다.
- 연결 상태와 검증 상태를 같은 초록 점으로 합치지 않는다.
- 검사 열 본문은 독립 세로 스크롤을 허용하고 하단 행동은 sticky footer로 유지한다.
- 기본 노출 상한은 사용 스킬·도구 4개, 참조 문서 4개, 최근 근거 3개다. 넘치면 `+N 더 보기`로 접고 전체 목록을 상세 안에 무한히 늘이지 않는다.
- 관계 한 건은 두 줄 고정 구조를 쓴다. 첫 줄은 `출발 개체 + 관계 동사`, 둘째 줄은 `대상 개체 + 상태`이며 관계 간에는 최소 16px을 둔다. 한 줄 화살표 문장으로 압축하지 않는다.

- 1280px 이상에서는 목록 오른쪽에 최대 360px 열로 연다. 열이 닫히면 그리드 열 자체를 제거한다.
- 768–1279px에서는 최대 420px modal sheet, 767px 이하에서는 전체 화면 상세로 전환한다.
- 상세를 닫으면 포커스가 선택했던 행으로 돌아간다.

## 콘텐츠·데이터 계약

| UI 개념 | 현재 읽을 수 있는 근거 | 구현 경계 |
| --- | --- | --- |
| Goal·Task | `projects.yaml`, `goals/*.md`, `/api/projects`, `/api/todos` | Task는 Goal Completion Check를 표시하고 별도 ID를 임의 생성하지 않음 |
| 일정 | `/api/calendar` | Calendar 원장에만 쓰며 Goal 완료와 자동 동기화 금지 |
| 문서·디자인 | `/api/docs`, `/api/docs/[...path]`, Git provenance | Qdrant는 검색 파생값, 프로젝트 Git이 산출물 정본 |
| 관계 | 프로젝트 상대경로·Git ref·결정 기록 | source ref 없는 관계를 verified로 표시 금지 |
| 운영 기록 | `/api/docs`, `/api/constellation`, vector API, 기존 status API | 서비스별 partial·stale·unknown 유지 |
| 스킬·도구 | 현재 production API 없음 | 별도 읽기 전용 catalog API 전에는 fixture를 실제 상태로 표시 금지 |

- 사용자에게 보이는 Phase·Goal·Task 이름은 `work-item-language-contract.md`의 문법을 따른다.
- `Issue`는 GitHub 등 외부 추적기의 안정적인 ID·URL이 있을 때만 표시한다. 로컬 blocker는 `막힘` 상태이지 가짜 Issue가 아니다.
- 개인·시스템 절대경로와 시크릿은 브라우저 payload에 포함하지 않는다.
- AI가 반환하는 상태·종류·관계 enum은 코드 allowlist를 통과한 값만 사용한다.

## 상호작용

- 상위 탐색과 하위 보기는 URL에 남고 새로고침·뒤로 가기 후 복원된다.
- 행 선택은 조건부 상세를 열고 선택 ID를 URL 또는 복원 가능한 상태에 남긴다.
- `Esc`는 검사 열을 닫고 포커스를 선택했던 행으로 되돌린다.
- `↑/↓`는 목록 행 이동, `Enter`는 선택, `Cmd/Ctrl+K`는 전역 검색·명령을 연다.
- 관계 항목 선택은 현재 검사 열 안에서 breadcrumb를 쌓되 두 단계 이상이면 전용 관계 보기로 이동한다.
- 페이지마다 주요 버튼은 하나를 우선한다. 동일 행동을 카드·행·footer에 반복하지 않는다.
- 위험하거나 쓰기를 일으키는 행동은 조건부 상세의 기본 버튼에 놓지 않는다.

## 반응형 변환

- 1280px 이상: 최대 1176px 중앙 셸. 조건부 상세가 열릴 때만 `minmax(0, 1fr) / 320–360px`로 나눈다.
- 768–1279px: 상단 탐색은 유지하되 간격을 줄이고 상세는 modal sheet로 전환한다.
- 767px 이하: 상위 탐색은 메뉴로 접고, 사실 2열은 1열, 목록은 핵심 열 우선 행으로 바꾸며 상세는 전체 화면으로 이동한다.
- R3 prototype의 `min-width:1180px`는 방향 확인용이다. production에 복제하지 않는다.
- 정보 순서와 이름은 폭이 바뀌어도 유지한다.

## 접근성과 품질 기준

- 주요 버튼과 모바일 표적은 최소 44×44px, 밀집 표의 아이콘 표적은 최소 24×24px과 8px 이상 간격을 확보한다.
- focus indicator는 2px 이상이며 주변 색과 3:1 이상 차이를 확보한다.
- 상태는 색만으로 전달하지 않고 텍스트와 아이콘을 함께 쓴다.
- 정본과 연결되지 않은 화면 시안은 목록과 검사 열 모두에 `예시 데이터`를 지속 표시한다. 실제로 확인된 집계값만 `정본 수량`으로 별도 표기한다.
- 브랜드 아이콘에는 도구 이름의 접근 가능한 이름을 제공한다.
- H1은 화면당 하나, 상위 탐색은 `nav`, 현재 화면은 `aria-current`, 목록은 실제 의미에 맞는 table/list/grid semantics를 사용한다.
- 본문 텍스트 대비 4.5:1, 큰 텍스트·의미 경계·focus 3:1 이상을 측정한다.
- 1440·1280·1024·768·390·360px에서 overflow, 잘림, 겹침, 이중 스크롤과 panel↔modal 경계를 검증한다.

| `src/components/vector/*` | 검색은 `지식·디자인`, 인덱스·ingest·reset 상태는 `운영 기록`으로 분리 |

`스킬·도구`는 새 읽기 모델과 API가 필요하므로 셸 작업에 끼워 넣지 않는다. 별도 Goal에서 catalog owner, 민감정보 제거, kind allowlist, 가용성 증거를 먼저 확정한다.

권장 구현 Goal 순서:

1. ✅ Goal 22 완료 — 현재 Home 진입을 유지한 채 live Goal·Task를 연결한 R3 `지금` 화면 구현
2. `작업`의 할 일·일정·프로젝트 형제 보기 구현
3. `지식·디자인`과 Vector 검색 역할 재배치
4. `스킬·도구` 읽기 계약과 화면 구현
5. `운영 기록` 감축 후 다섯 상위 탐색을 한 번에 전환하고 전체 회귀 검증

각 Goal은 독립 build·test·visual QA가 가능해야 하며 한 Goal에서 다섯 화면을 동시에 바꾸지 않는다. 아직 구현되지 않은 화면을 빈 상위 탭으로 먼저 노출하지 않는다.

## 검증 계획

| Check | 조건 | Threshold | Evidence |
| --- | --- | --- | --- |
| 작업 언어 | 실제 Goal·Task·Issue fixture | Phase·Goal·Task 의미 중복 0, 가짜 Issue 0 | DOM text audit + fixture |
| 핵심 위계 | 각 화면 기본 상태 | H1 1개, 주요 행동 1개, 14px 미만 설명 0 | Playwright computed style |
| 반응형 | 1440·1280·1024·768·390·360px | 가로 overflow 0, 가려진 행동 0, 상세 focus 복귀 | screenshots + DOM readings |
| 상태 | empty·loading·error·partial·stale·success·selected·disabled·destructive | 해당 상태별 문구·허용 행동 명시, 색 단독 전달 0 | state fixture matrix |
| 접근성 | 키보드·스크린리더 이름·대비 | 모든 행동 키보드 도달, focus 3:1, 본문 4.5:1 | axe/manual keyboard + contrast readings |
| 실제 데이터 | 가장 긴 실제 한국어 이름·경로·상태 | H1 최대 2줄, 표 핵심 열 유지, 경로 안전 축약 | longest-content fixture |
| 보안·쓰기 경계 | API payload와 위험 행동 | 시크릿·절대경로 0, destructive same-origin·사람 게이트 유지 | route tests + payload inspection |
| 품질 게이트 | 구현 Goal마다 | `typecheck`, `lint`, `test`, `build` 모두 exit 0 | command logs |

Gate 자체는 고의로 긴 이름, 누락 source, 잘못된 enum, 가짜 Issue가 있는 broken fixture가 실패하는지 먼저 확인한다.

## 범위 밖과 잔여 위험

- 이 명세 자체는 commit·push·배포를 승인하지 않는다. production 수정은 별도 승인된 Goal 22 범위에서만 수행됐고 배포는 하지 않았다.
- 실제 탭 사용 빈도 데이터가 없어 기능 삭제가 아니라 화면 소유권 이동으로 설계했다. [확신 중간]
- Goal 22은 360·432·768·1280·1440px와 live·multiple·empty·error·loading 상태를 통과했다. 1024·390px는 동일 breakpoint 구간이지만 이번 구현 QA의 직접 측정 폭에는 포함되지 않았다. [확신 높음]
- 현재 Goal 23만 IN_PROGRESS이며 Goal 13·21·22는 DONE이다. 향후 다시 복수 활성 Goal이 생겨도 UI는 하나를 임의 선택하지 않는다. [확신 높음]
- 스킬·도구 production data source가 없으므로 현재 집계값으로 화면을 먼저 만들면 가짜 상태가 된다. [확신 높음]
