# 지식 검토 디자인 결정 로그

## 2026-08-22 — 정보 위계와 승인 후 연결

- 상태: 채택
- 결정자: 요한
- 근거: 대화에서 제목·부제목·본문의 강약 부족, 주장 행 정렬과 줄 간격, 승인 후 흐름 부재를 직접 지적했다.

### 결정

1. 작업면 제목은 20~24px, 섹션 제목은 18~20px, 본문은 16px, 보조 설명은 14px로 계층을 고정한다.
2. 주장 행은 데스크톱에서 9.5rem 메타 열과 본문 열로 나누고 모바일에서는 한 열로 쌓는다.
3. 주장 본문은 72자 폭을 넘기지 않고 28px 줄 간격을 쓴다. 인용문은 왼쪽 선과 보조 대비만 사용한다.
4. 목록 카드에서는 원본 종류·제목·요약·승인 가능 여부만 기본 노출한다.
5. 승인 후 상세 영수증에는 사람 승인, RESOURCE, SUMMARY의 세 단계를 보여 주고 실제 인사이트 열기와 다음 검토 CTA를 제공한다.
6. 재진입 뒤에도 문서 원장에서 최근 승인된 인사이트를 찾아 얇은 연결선 형태로 보여 준다.
7. 내부 경로와 해시는 서버 검증에만 쓰고 공개 영수증에는 노출하지 않는다.
8. 다음 검토 자동 이동은 상위 `overflow-hidden` 조상을 움직이는 `scrollIntoView` 대신 지식 검토 컨테이너만 직접 스크롤한다.

### 반대안과 기각 이유

- 성공 토스트만 표시: 결과와 다음 행동이 없어 사용자가 승인이 어디로 이어졌는지 알 수 없다.
- 경로·해시를 그대로 표시: 디버깅에는 유용하지만 로컬 구조가 브라우저 계약으로 새고 읽기 집중을 해친다.
- 모든 단계를 색상 배지로 표시: 이미 지적된 시선 분산을 반복한다. 상태색은 아이콘과 짧은 상태 문구에만 제한한다.
- 승인 완료 화면을 별도 페이지로 분리: 탭 5개 상한과 한 화면 작업 흐름을 깨고 과도한 이동을 만든다.

### 재검토 조건

- 최근 승인 문서가 여러 원본을 병합하는 구조로 바뀌는 경우
- RESOURCE·SUMMARY 외 새 승인 산출물이 추가되는 경우
- 승인 이력 화면이 별도 Goal로 채택되는 경우
