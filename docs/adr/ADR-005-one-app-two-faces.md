# ADR-005: 관제탑은 지식 OS와 별도이며, 탑 안에 앱과 대시보드만 둔다

> `ADR-004`는 PR #40의 일상 표면 색이다. 이 문서는 제품이 사는 곳이라 `005`다.

## 맥락 (Context)

이 레포는 2026-06-25 벡터 인제스트 **대시보드**로 시작했다. 2026-07에 `yohan-brain/dashboard`(당시 화면 이름 **Yohan OS**)를 이관했다. 2026-08-07에 개인 달력이 붙었다.

그 결과 로컬 `:3001`을 열면 지식 웹앱(요한 OS)과 관제탑이 **한 창**으로 보인다. 헤더·탭 제목이 "Yohan OS"여서 겹침이 더 커졌다.

질문은 세 집(노션 / 관제탑 / 새 앱) 중 어디냐와, 관제탑이면 사람 하루와 에이전트 한눈을 **앞문·뒷문**으로 나눌지였다. 오너 정정: 앞·뒤가 아니라 **앱**과 **대시보드** 두 가지다. 이어진 정정: **요한 OS는 지식 웹앱이고 관제탑과 별도**다. brain은 서랍이지 OS가 아니다.

노션은 무겁다. 지금 단순 공사는 어렵다. 할 일 전용 새 앱은 집을 늘린다. 지식 탭을 지금 새 레포로 쪼개는 것도 같은 종류의 공사다.

## 결정 (Decision)

**권고 (사람 확인 전):**

- **요한 OS**와 **요한 관제탑**은 별도 제품이다. 이 레포의 화면 이름은 관제탑이다. "Yohan OS"로 쓰지 않는다.
- **brain**은 파일 서랍이다. `YOHAN_OS_ROOT`는 그 경로의 옛 env 이름이다. 이름을 지금 바꾸지 않는다.
- 관제탑 **앱:** 달력, 일상 할 일. 스스로 관리. 집 에이전트는 달력 마크다운을 읽는다.
- 관제탑 **대시보드:** 프로젝트, 에이전트, 스킬, 로그.
- 설치는 관제탑 하나. 할 일 전용 새 앱은 안 만든다. 지식 OS를 이 창에 한 번 더 그리지 않는다.
- 지식 탭이 이 코드에 남아 있는 것은 이관 잔재다. 지금 분리 공사하지 않는다. 새 조각에 OS 가짜를 넣지 않는다.
- 노션은 달력 본사가 아니다. ChatGPT 등 집 밖 LLM이 파일을 못 열 동안 **다리**로만 남긴다.
- 이용권(기간·횟수), 연주회=이벤트+프로젝트 링크, 집 밖 MCP는 달력 껍질(Goal 25) 다음이다. 기준: `docs/product/life-calendar-criteria.md`.
- 저장소 이름은 지금 바꾸지 않는다.
- 뒤집는 조건: 앱을 집 밖 폰에서 항상 써야 해서 대시보드(로컬)와 런타임이 갈라질 때. 또는 지식 OS를 별도 프로세스로 되돌릴 때.

## 대안 (Alternatives)

1. 노션(+ 노션 캘린더) 정본 — 폰은 편하다. 안 쓰게 된 상태 유지. 기각.
2. 할 일 앱만 새 저장소 — 단순해질 수 있다. 집이 늘고 에이전트 연결이 끊긴다. 지금 기각.
3. 지식 OS를 지금 이 레포에서 분리 — 겹침은 줄어든다. 대청소·새 앱과 같다. 지금 기각.
4. 관제탑 한 설치(앱+대시보드), 화면 이름은 관제탑, OS와 별도 — 권고.

## 결과 (Consequences)

- Goal 25는 앱 쪽 달력 껍질이다. 대시보드 한눈·지식 OS 분리와 한 세션에 섞지 않는다.
- 이슈 #1 검수 대시보드는 대시보드 쪽 후속이다.
- 브라우저 제목·헤더·매니페스트는 `src/lib/product.ts`가 정본이다.
- 사람이 새 앱이나 리네임을 고르면 이 ADR을 고친다.
