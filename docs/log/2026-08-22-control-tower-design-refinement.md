# 2026-08-22 관제탑 선택 시안 세부 설계

## 결과

- 사용자가 선택한 3안의 어두운 셸·밝은 작업면·명확한 아이콘을 기본 시각 방향으로 기록했다.
- 2안의 문서 근거·관계 표현을 결합하고, 우측 `작업 맥락`을 본문과 정렬된 360px 검사 열로 재설계했다.
- `design-team`의 구성 역할, 사용 스킬·도구, 참조 문서, 관계, 최근 근거, 다음 일정을 전체 프롬프트 없이 요약하는 계약을 만들었다.
- 문서 라이브러리·Design Intelligence·캘린더가 동일한 관계·역링크 모델을 사용하도록 명세했다.
- production UI 코드는 수정하지 않았다.

## 4차 상태 보정 — MCP·훅·플러그인

- 같은 밝은 중립 셸에서 `mcp.yohan`, `session-title`, `critical-thinking`을 각각 선택한 검사 열 미리보기를 만들었다.
- MCP는 연결 정보와 필요한 환경 설정 이름만 표시하고, 보안 가드가 차단한 원본 command·args·env와 미확인 transport·기능 수를 노출하거나 추정하지 않았다.
- 훅은 처리 대상·이벤트 연결·실패 정책·제한 시간을, 플러그인은 지원 환경·버전·호환 범위·포함 항목을 보여주도록 분리했다.
- `훅` 글자가 ImageGen에서 반복해서 `흑`으로 오렌더링됐으며, 정확한 문자 교정 요청도 실패했다. 해당 래스터는 구조 참고안이지 텍스트 통과본이 아니다.
- 세 상태의 preview 크기는 1486–1487×1058이었다. 1440×1024 실측과 상호작용 검증은 native prototype 단계로 남겼다.
- 생성 이미지는 사용자 승인 전이므로 프로젝트 정본으로 승격하지 않았다. production UI도 수정하지 않았다.

## 2차 보정 — 다중 화면 정보구조

- 사용자 피드백에 따라 깨진 생성 glyph를 폐기 대상으로 명시하고, 실제 구현은 Lucide named icon과 검증된 공식 브랜드 자산만 사용하도록 고정했다.
- `오늘 14:00`은 실제 일정이 아닌 이전 시안용 mock data였음을 기록했다. 자동화 자산에는 검증된 Calendar 관계가 있을 때만 `관련 검토` 역링크를 표시한다.
- 상위 탐색을 `지금 / 작업 / 지식·디자인 / 자동화 자산 / 운영 기록`으로 다시 제안했다. `작업`은 `할 일 / 일정 / 프로젝트`를 직접 선택 가능한 형제 보기로 제공한다.
- Agent Kit canonical catalog 197개와 12 kind를 확인했다. 네 facet은 탐색용 제안이며 raw kind는 보존한다.
- 작업, 자동화 자산, 지식·디자인의 세 화면군을 동일한 1487×1058 미리보기 조건으로 생성했다. 검사 열은 400px 기준으로 넓히고 관계는 두 줄 블록으로 분리했다.
- production UI 코드는 수정하지 않았고, 생성 PNG도 사람 승인 전이라 프로젝트 정본으로 승격하지 않았다.

## 3차 도메인 보정 — 종류별 상세와 시각 위계

- 사용자 피드백에 따라 1안은 폐기하고 2안의 간결한 골격과 3안의 단순 상세를 결합하는 방향으로 좁혔다.
- 시니어 개발 도메인 검토에서 `Codex`가 역할자가 아니라 실행 환경이며, 역할·클라이언트·모델·관리 주체·사용 도구를 분리해야 함을 확인했다.
- `design-team`의 역할은 고정 조직도가 아니므로 정적 스킬 상세에서 제거하고 실제 실행 영수증이 있을 때만 `이번 작업의 역할`을 표시하도록 보정했다.
- 현재 Agent Kit 정본은 이전 조사 시점의 197개가 아니라 201개다. 수량 하드코딩을 금지하고 종류별 수를 카탈로그 응답에서 계산하도록 계약했다.
- 기본 화면 용어를 `스킬·도구`와 실제 종류명으로 되돌렸다. `자동화 자산`, 네 개 조어 facet, `기타` 집계는 다음 시안에서 사용하지 않는다.
- 검정 패널 중심 셸을 폐기하고 Mova의 밝은 중립색, 축소된 좌우 패널, 제한된 타입 스케일을 다음 시안 기준으로 정했다.
